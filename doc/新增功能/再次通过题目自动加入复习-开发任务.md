# 已有题目再次通过后自动加入复习：开发任务

创建日期：2026-08-07  
状态：未开始  
建议优先级：P1  
适用范围：个人本地 MVP，不改变公开发布 NO-GO 结论

## 1. 文档用途

本文档用于拆解“题库中的已有题目在力扣再次通过并完成同步后，自动加入复习”的开发工作、产品边界、技术影响和验收标准。

本文档是功能开发明细，不替代 `doc/LeetCode复习插件任务清单.md` 作为全局任务状态来源。正式开始实现时，应在主任务清单中增加或链接本功能；任务完成后再根据实际测试和验收证据更新状态。

本轮只产出开发任务文档，不修改代码、状态版本、测试或现有产品文档。

## 2. 背景与当前行为

项目当前已经支持设置 `settings.newQuestionMode`：

- `pending`：新同步到题库的题目进入“待确认”；
- `reviewing`：新同步到题库的题目自动进入“复习中”。

现有同步引擎只在创建新题时读取该设置。对于题库中已经存在的题目，再次同步只更新来源元数据，并完整保留原有 `review`、`reviewHistory` 和 `note`，不会因为近期通过时间变化而把“待确认”题目自动加入复习。

力扣近期通过接口 `recentACSubmissions` 已能提供有限范围内最新一次通过时间。该数据可以用于识别“上次成功同步以后，用户又通过了这道题”，但接口读取失败时只产生 warning，且不能覆盖完整历史。

## 3. 功能目标

在“计划设置”中增加一个独立开关：

> 再次通过后自动加入复习

开启后，如果题库中的已有题目在上次成功同步之后产生新的通过记录，并且该题当前处于“待确认”，同步完成后将其自动切换为“复习中”。

关闭时保持现有行为，不根据再次通过记录改变任何本地复习状态。

“自动加入复习”只表示题目具备参与计划计算的资格，不承诺强制插入当天任务。是否进入今日任务仍由计划状态、每日容量、优先级和下一次计划重算共同决定。

## 4. 非目标

本功能不包含以下内容：

- 不读取或保存用户提交代码、失败提交、运行结果或单题完整提交历史；
- 不新增按题目请求 `submissionList` 的同步方式；
- 不把新通过题强制放入今日任务并突破每日容量；
- 不重置已有 FSRS 卡片、到期时间、掌握程度或复习历史；
- 不自动恢复用户明确设置为暂停、已毕业或忽略的题目；
- 不改变新题的 `newQuestionMode` 规则；
- 不解决 `recentACSubmissions` 只能覆盖有限近期记录的平台限制；
- 不扩大到 `leetcode.com`、多账号或云端多设备同步。

## 5. 产品规则

### 5.1 设置项

建议新增持久化字段：

```text
settings.autoJoinReacceptedQuestions: boolean
```

规则：

- 默认值为 `false`，升级后维持当前产品行为；
- 设置页面使用开关控件，不与“新同步题目”的下拉选择合并；
- 开启或关闭只影响后续同步，不批量修改当前题库；
- 保存失败时界面必须显示错误，不能只在前端表现为已开启；
- 设置应随本地备份导出和恢复，不发送到服务器。

建议界面分组：

```text
再次通过题目
[开关] 再次通过后自动加入复习
```

### 5.2 “再次通过”的确定性定义

只有同时满足以下条件，才认定为一次新的再次通过事件：

1. 本轮同步前，本地题库中已经存在该题；
2. 本轮远端题目包含有效的 `acceptedAt`；
3. `acceptedAtSource` 为 `recent_accepted_submission`；
4. 本地题目已经有有效的 `lastSourceSeenAt`；
5. 本轮 `remote.acceptedAt` 严格晚于同步前的 `existing.lastSourceSeenAt`。

建议判断表达式：

```text
isReaccepted =
  existingQuestion
  && remote.acceptedAt is valid
  && existing.lastSourceSeenAt is valid
  && remote.acceptedAt > existing.lastSourceSeenAt
```

不得只使用“本轮 `acceptedAt` 与本地 `acceptedAt` 不同”作为判断条件。近期通过接口从失败恢复后，可能只是补齐旧的时间元数据；如果该时间早于上次同步，就不应误判为用户再次做题。

对于旧版本数据中缺少 `lastSourceSeenAt` 的题目，第一次同步只补齐来源字段，不触发自动加入。后续出现严格晚于已记录 `lastSourceSeenAt` 的通过时间时再触发。

### 5.3 状态处理矩阵

| 开关 | 再次通过 | 同步前状态 | 同步后状态 | 说明 |
| --- | --- | --- | --- | --- |
| 关闭 | 是或否 | 任意状态 | 保持原状态 | 完全兼容现有行为 |
| 开启 | 否 | 任意状态 | 保持原状态 | 普通重复同步不得改状态 |
| 开启 | 是 | `pending` | `reviewing` | 本功能唯一自动状态转换 |
| 开启 | 是 | `reviewing` | `reviewing` | 不重置现有调度数据 |
| 开启 | 是 | `paused` | `paused` | 尊重用户明确暂停 |
| 开启 | 是 | `graduated` | `graduated` | 尊重用户明确毕业 |
| 开启 | 是 | `ignored` | `ignored` | 尊重用户明确忽略 |

这项限制用于维持“用户始终拥有是否复习某道题的最终决定权”。如果未来希望再次通过能够恢复暂停、毕业或忽略状态，必须作为新的产品决策单独评审，不能顺带实现。

### 5.4 数据保护规则

从 `pending` 自动切换为 `reviewing` 时：

- 保留 `isFocus`、`mastery`、`fsrs`、`reviewHistory`、`note` 和来源元数据；
- 不清空或伪造历史反馈；
- 不生成一条正式复习反馈记录；
- `updatedAt` 设置为本次同步时间；
- `updatedByDeviceId` 设置为当前设备 ID；
- 如果没有 FSRS 卡片，`dueAt` 保持 `null`，按现有首次复习候选规则处理；
- 如果异常旧数据中已经存在 FSRS 卡片或 `dueAt`，不得擅自重置。

### 5.5 幂等与同步结果

同一个近期通过时间在后续重复同步时不得再次触发状态转换或重复计数。

建议在同步结果中增加：

```text
reaccepted: number
autoJoinedReview: number
```

- `reaccepted`：本轮识别到的已有题再次通过数量；
- `autoJoinedReview`：其中从 `pending` 自动切换到 `reviewing` 的数量；
- 已经处于 `reviewing` 或受保护状态的题目可以计入 `reaccepted`，但不能计入 `autoJoinedReview`；
- 两个字段进入同步历史，便于定位行为；
- 弹窗同步摘要可展示“自动加入复习 N 题”，为 0 时可以隐藏；
- 现有 `added`、`updated`、`unchanged`、`failed` 和 `conflicts` 的语义不得改变。

## 6. 持久化与迁移方案

建议将 `schemaVersion` 从 `4` 升级到 `5`，明确记录新增持久化设置字段。

迁移要求：

- 版本 4 及更早状态缺少该字段时补为 `false`；
- 已有题目、连接状态、同步历史、计划、笔记和复习历史保持不变；
- 迁移后立即按现有存储流程持久化；
- 导入旧备份时执行同一归一化规则；
- 不重命名 `newQuestionMode`，避免把“新题规则”和“再次通过规则”混为一个字段。

## 7. 建议实现边界

### 7.1 `src/core/state.js`

- 在默认设置中增加 `autoJoinReacceptedQuestions: false`；
- 升级 `SCHEMA_VERSION`；
- 归一化旧状态时严格得到布尔值；
- 保持其他设置和题目字段不变。

### 7.2 `src/core/library.js`

- 增加设置更新纯函数，校验输入必须为布尔值；
- 或提取可复用的题目状态转换函数，供同步引擎安全执行 `pending -> reviewing`；
- 不复制一套与现有 `transitionReview` 不一致的状态规则。

### 7.3 `src/core/sync-engine.js`

- 在覆盖 `lastSourceSeenAt` 之前，使用同步前的 existing 数据判断再次通过；
- 只对本轮之前已经存在的题目执行判断；
- 新增题仍只读取 `newQuestionMode`；
- 开关开启且状态为 `pending` 时执行自动加入；
- 保护 FSRS、历史、笔记和其他用户字段；
- 增加同步结果计数并保持重复同步幂等；
- 近期通过时间缺失、无效或接口 warning 时不触发自动加入。

### 7.4 `src/background.js`

- 在 `UPDATE_REVIEW_SETTINGS` 中保存新字段；
- 向工作台返回更新后的设置；
- 如同步结果增加摘要字段，确保公开状态和弹窗读取路径兼容旧同步历史中字段缺失的情况。

### 7.5 `src/app/`

- 在计划设置中增加独立开关；
- `renderSettings` 正确回填开关状态；
- 表单提交时发送布尔值；
- 保存成功后以后台返回值为准重新渲染；
- 检查 1440px 和 390px 视口，无横向溢出、文字截断或控件重叠。

### 7.6 `src/popup/`

- 如果采用 `autoJoinedReview` 同步摘要，增加相应展示；
- 老同步记录没有该字段时按 0 处理；
- 不增加完整题库数据返回。

### 7.7 无需修改的来源边界

正常情况下不需要修改 `src/content-script.js` 的 GraphQL 查询。现有 `recentACSubmissions` 已按题目 slug 保存最新一次近期通过时间。本功能应优先消费已有快照字段，不新增按题请求或提高请求频率。

## 9. 自动化测试用例

### 9.1 设置与迁移

- schema 4 状态迁移后新开关默认为 `false`；
- schema 5 状态中的 `true` 能够保留；
- 迁移不改变已有题目状态、FSRS、历史或笔记；
- 设置更新接受 `true`、`false`，拒绝非布尔值；
- 设置页面加载、修改、保存和重载后值一致。

### 9.2 再次通过识别

- `remote.acceptedAt` 晚于 `existing.lastSourceSeenAt` 时识别为再次通过；
- 时间相等时不识别；
- 时间更早时不识别；
- `acceptedAt` 缺失或无效时不识别；
- `lastSourceSeenAt` 缺失时不识别，只补齐同步字段；
- 近期通过接口失败并产生 warning 时不改变复习状态；
- 新题即使带有近期通过时间，也只服从 `newQuestionMode`。

### 9.3 状态与数据保护

- 开关关闭时，再次通过的 `pending` 题仍为 `pending`；
- 开关开启时，再次通过的 `pending` 题变为 `reviewing`；
- 已经 `reviewing` 的题保持原有 `dueAt`、FSRS、掌握程度和历史；
- `paused`、`graduated`、`ignored` 均保持原状态；
- 笔记、重点标记、复习历史和题目主键保持不变；
- 来源元数据仍按现有规则更新；
- slug 回退主键升级场景中只处理一次，不生成重复题。

### 9.4 幂等与事务

- 同一个再次通过时间连续同步两次，只在第一次计入 `reaccepted` 和 `autoJoinedReview`；
- 手动同步与自动同步竞争时仍由 `syncInFlight` 和 `operationQueue` 串行化；
- 同步失败时不保存半完成的状态转换；
- 账号不匹配、分页不完整或来源结构异常时，题库和新设置保持完整；
- 老同步历史缺少新增计数字段时，弹窗和工作台不报错。

### 9.5 计划边界

- 自动加入后题目具备后续计划候选资格；
- 不突破每日题数或时间容量；
- 不撤销当天已完成、已跳过任务；
- 全局计划暂停时可以更新题目为 `reviewing`，但不得生成今日任务或提醒；
- 不因自动加入伪造一次复习反馈或计划完成记录。

## 10. 人工验收步骤

1. 加载升级后的扩展，确认旧本地数据仍存在且开关默认关闭。
2. 选择一道人为保持“待确认”的已有题，记录其笔记、重点状态和同步前 `lastSourceSeenAt`。
3. 在力扣再次通过该题，等待近期通过记录可见后执行手动同步。
4. 开关关闭时，确认该题仍处于“待确认”。
5. 再选择另一道“待确认”题，开启“再次通过后自动加入复习”并保存。
6. 在力扣再次通过该题后同步，确认其状态变为“复习中”。
7. 确认题目没有重复，笔记、重点和历史未丢失，同步摘要数量正确。
8. 对暂停、已毕业或忽略题执行一次等效数据验证，确认状态不被自动恢复。
9. 重新加载扩展，确认设置和题目状态持久化。
10. 检查今日任务仍受每日容量和全局暂停规则约束。

人工验收必须记录日期、版本、浏览器版本、测试账号、同步前后状态和截图。若近期通过接口没有及时返回目标记录，应记录为外部数据限制，不能通过手改本地状态冒充真实来源验收。

## 11. 完成标准

只有同时满足以下条件，才能将本功能标记为完成：

- 设置项能够保存、回填，并在扩展重载后保持；
- 再次通过判定严格使用同步边界，不把旧时间补齐误判成新事件；
- 只自动执行 `pending -> reviewing`，不覆盖用户明确状态；
- 同步失败和重复同步不会造成状态损坏或重复计数；
- 新题规则、题目去重、账号隔离和来源冲突行为无回归；
- `npm run check`、`npm test`、`npm run smoke` 全部通过；
- 1440px、390px 和 368px 相关页面无布局回归；
- 至少完成一次真实账号最小人工验收并保存证据；
- 主任务清单、使用说明、验收记录和 `AI_HANDOFF.md` 已按实际结果更新。

## 12. 风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 近期通过接口只返回有限记录 | 较早的再次通过无法触发 | 明确为尽力而为，只处理同步时可见的近期记录 |
| 接口短暂失败后补齐旧时间 | 误把旧记录当成再次通过 | 必须与同步前 `lastSourceSeenAt` 比较 |
| 自动状态修改覆盖用户决定 | 暂停、毕业或忽略被意外恢复 | 仅允许 `pending -> reviewing` |
| 重复同步反复触发 | 重复计数或错误重排 | 使用严格时间边界并增加幂等测试 |
| 加入复习后当天任务超量 | 用户计划突然膨胀 | 不强制插队，继续服从容量和计划重算规则 |
| 新设置破坏旧数据 | 升级后行为突变或字段丢失 | 默认关闭、schema 迁移、旧状态回归测试 |
| 把来源可访问误述为已获授权 | 扩大合规风险 | 保持个人本地 MVP，公开发布和商业化仍为 NO-GO |
