## 2. 决策摘要

| 任务 | 决策结果 |

| `T-002` | 技术上可读取题目元数据、登录用户解题状态和有限的近期通过记录；接口非公开且无稳定性承诺，公开发布前必须解决授权问题。 |

## 3. T-001：运行平台与支持范围

### 3.1 首版平台

- 产品形态：桌面浏览器扩展。
- 扩展规范：Chromium Manifest V3。
- 支持浏览器：Google Chrome、Microsoft Edge。
- 版本范围：发布时最新两个稳定大版本。
- 首版站点：仅支持 `https://leetcode.cn`。
- 界面语言：简体中文。
- 登录方式：用户先在普通 LeetCode 页面完成登录，扩展只识别现有登录状态，不提供独立的账号密码输入框。

### 3.2 暂不支持

- Firefox、Safari 及其他非 Chromium 浏览器；
- Android、iOS 等移动端浏览器；
- `leetcode.com` 全球站账号；
- 同时连接多个 LeetCode 账号；
- 独立桌面客户端。

### 3.3 决策理由

Chrome 与 Edge 共用 Chromium 扩展体系，可以复用同一套首版能力；Manifest V3 是当前 Chrome 扩展规范。限定最近两个稳定大版本可以控制兼容性和测试范围。

## 4. T-002：账号与刷题记录读取可行性

### 4.1 技术验证结果

2026-07-31 对 `leetcode.cn` 当前网站进行了只读验证：

| 验证项 | 结果 |
| --- | --- |
| `https://leetcode.cn/graphql/` | 端点存在；无有效查询时返回 `400`。 |
| 当前题单查询 | `problemsetQuestionListV2` 可返回题目元数据、题目状态、总数和分页信息。 |
| 匿名请求 | 可读取公开题目元数据，但用户完成数量为 `0`，不能替代登录用户数据。 |
| 近期通过查询 | `https://leetcode.cn/graphql/noj-go/` 的 `recentACSubmissions` 可返回近期通过题目的提交时间和题目信息。 |
| 近期记录数量 | 抽样公开用户每次返回 15 条，不能代表完整刷题历史。 |
| 单题提交记录 | 当前前端存在分页 `submissionList` 查询，但它按题目读取且依赖登录态，不适合作为全量历史同步方案。 |
| 接口变更情况 | 常见旧版 `questionList` 查询已在中国站失效，证明字段和操作存在变化风险。 |
| 官方第三方 API | 本次调查未发现面向第三方插件、具有版本和服务承诺的官方公开 API。 |

本次验证没有使用用户登录会话。因此，“登录用户全量已通过状态”必须在开发阶段使用专用测试账号完成最终验证，不能把匿名响应当作账号同步已经验收通过。

### 4.2 首版读取策略

首版采用低频、只读、用户主动触发的读取方式：

1. 用户在 `leetcode.cn` 页面保持登录。
2. 用户点击“同步”后，扩展确认当前登录状态。
3. 扩展分页读取当前账号的题单状态，只导入“已通过”的题目。
4. 扩展读取有限的近期通过记录，用于补充能够可靠获得的完成时间。
5. 扩展不复制、不导出、不持久化 LeetCode Session Cookie、CSRF 值或账号密码。
6. 扩展不扫描其他用户主页，不读取讨论区，不抓取题解，不下载提交代码。
7. 首版 `P0` 只要求用户主动同步；自动定时同步保持为 `P1`。

接口访问必须通过独立的数据适配层。接口异常时停止本轮同步并保留已有数据，不能把空响应解释为用户题库已经清空。

### 4.3 合规与持续性结论

力扣用户服务协议第 3.1.6 条限制未经书面授权的访问或使用；第 3.1.7 条限制未经授权的插件或第三方工具对服务运行造成干扰。`leetcode.cn/robots.txt` 还禁止自动访问 `/submissions`、`/api`、`/accounts`、`/progress`、`/u/` 等路径。

据此作出以下决策：

- **个人本地原型：有条件 GO。** 可以继续验证复习功能的实际价值，但应保持低频、只读和最小权限，不对外分发。
- **公开商店发布：NO-GO。** 发布前需要获得力扣书面许可，或者改用力扣明确允许的官方 API、官方数据导出或其他经确认的合规数据源。
- **商业化：NO-GO。** 除满足公开发布门槛外，还需要单独完成法律、隐私和平台政策审查。

上述内容是产品与工程风险判断，不构成法律意见。

## 5. T-003：可读取数据字段

### 5.1 字段清单

| 业务字段 | 数据来源 | 可用性 | 首版处理方式 |
| --- | --- | --- | --- |
| 平台内部题目 ID | 题单查询 | 可用 | 用于来源追踪，不作为跨站唯一标识。 |
| 前台题号 | 题单查询 | 可用 | 用于展示和搜索。 |
| 英文标题 | 题单查询 | 可用 | 完整保留。 |
| 中文标题 | 题单查询 | 可用 | 优先展示；缺失时使用英文标题。 |
| `titleSlug` | 题单查询 | 可用 | 用于题目链接和站内去重。 |
| 难度 | 题单查询 | 可用 | 映射为简单、中等、困难；未知值保留为“未知”。 |
| 标签 | 题单查询 | 可用 | 允许为空，不阻断同步。 |
| 付费题标识 | 题单查询 | 可用 | 用于提示访问限制。 |
| 解题状态 | 登录态题单查询 | 待测试账号终验 | 只导入“已通过”，其他状态不进入复习计划。 |
| 近期通过时间 | 近期通过查询 | 有限可用 | 仅覆盖接口返回的近期记录，并保存时间来源。 |
| 完整历史首次通过时间 | 无稳定批量来源 | 不可依赖 | 显示“未获取”，不能伪造成真实完成时间。 |
| 失败提交详情 | 非首版范围 | 不读取 | 不保存失败次数、代码和运行错误。 |

### 5.2 历史完成时间规则

- 能从近期通过记录可靠匹配的题目，保存实际通过时间，来源标记为 `recent_accepted_submission`。
- 无法取得历史通过时间的旧题，保存首次同步时间，来源标记为 `first_sync_baseline`。
- 首次同步时间只用于生成初始复习计划；界面显示“历史完成时间未获取”，不得显示成“完成于某日”。
- 安装扩展后的新通过题目，可在后续同步中记录平台提供的通过时间。
- 所有时间统一保存为时间戳，并按用户当前时区展示。

## 6. T-004：异常与字段缺失处理

| 场景 | 首版处理规则 |
| --- | --- |
| 未登录 | 不发起账号数据同步；提示用户前往 `leetcode.cn` 登录。 |
| 会话失效 | 标记为“需要重新登录”，保留全部本地题库和复习记录。 |
| 网络断开或请求超时 | 本轮同步失败；展示重试入口；不修改已有数据。 |
| 平台限流 | 停止继续请求，延迟后允许手动重试；禁止无限自动重试。 |
| 接口字段或结构变化 | 校验失败并停止写入；保留原数据；显示“同步暂不可用”。 |
| 返回空题单 | 未确认账号确实为空前，不执行全量删除。 |
| 缺少中文标题 | 使用英文标题。 |
| 缺少难度 | 标记“未知”，题目仍可复习。 |
| 缺少标签 | 使用空标签列表，题目仍可复习。 |
| 缺少完成时间 | 使用首次同步基准生成计划，但不伪造完成日期。 |
| 缺少题号但存在内部 ID 和 slug | 允许导入并标记字段不完整。 |
| 缺少 ID 和 slug | 隔离记录并计入同步失败数，不写入正式题库。 |
| 题目下线或链接失效 | 保留历史数据，标记“当前不可访问”，停止安排新复习。 |
| 付费题当前不可访问 | 保留题目并提示访问受限，由用户决定暂停或移出。 |
| 同步时关闭扩展 | 已确认批次保持一致，未完成批次不生效，下次可以重试。 |

## 7. T-005：题目纳入范围

首版只纳入同时满足以下条件的题目：

- 来源为当前连接的 `leetcode.cn` 账号；
- 平台状态明确为已通过；
- 具有可稳定识别的内部 ID 或 `titleSlug`；
- 普通题和已通过的付费题均可导入，付费访问限制单独标识。

首版不纳入：

- 只有失败提交、从未通过的题目；
- 只收藏但未通过的题目；
- 比赛中未形成普通题目标识的临时记录；
- 讨论、题解、平台笔记、提交代码和运行结果；
- 其他用户的做题记录。

“同步到个人题库”和“加入复习计划”是两个独立状态。用户始终可以决定某道已通过题是否参与复习。

## 8. T-006：本地数据范围与生命周期

### 8.1 保存的数据

- 连接站点和最小账号标识；
- 题目 ID、题号、标题、slug、难度、标签和付费标识；
- 平台解题状态及最后同步时间；
- 完成时间、完成时间来源及是否缺失；
- 用户设置的复习状态、重点状态和掌握程度；
- 复习计划、下次复习时间和复习历史；
- 用户主动填写的复习笔记；
- 每日容量、提醒偏好和同步偏好；
- 最近 50 次同步结果，用于错误排查。

### 8.2 不保存的数据

- LeetCode 明文密码；
- LeetCode Session Cookie、CSRF 值、访问令牌或其他登录凭据；
- 用户提交的代码；
- 完整提交明细、运行时间、内存结果和错误输出；
- 与复习无关的个人资料、讨论、私信或浏览记录；
- 其他 LeetCode 用户的数据。

### 8.3 保存位置

- 业务数据保存在当前浏览器扩展的本地数据库中。
- 少量偏好设置保存在扩展本地设置区。
- 首版不建设云端账号、远程数据库或跨设备同步。
- 默认不把用户数据发送给开发者或第三方分析服务。

### 8.4 保留与删除

- 题库、复习记录和笔记保留到用户主动删除或卸载扩展。
- 最近 50 次同步结果按数量滚动覆盖，不永久积累。
- “解绑账号”默认停止同步并保留本地复习数据，操作前明确告知用户。
- “删除账号数据”删除该账号关联的题库、计划、历史、笔记和同步记录，并要求二次确认。
- “清除全部数据”删除插件保存的所有本地数据和设置，并要求二次确认。
- 用户可以在删除前导出数据；设置页需要提供常驻导出入口。

## 9. T-007：首版成功指标

### 9.1 技术与数据指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 登录识别成功率 | 已登录且在支持环境中被正确识别的次数 / 有效尝试次数 | `>= 95%` |
| 首次同步成功率 | 成功生成可用题库的次数 / 有效首次同步次数，排除平台确认故障 | `>= 95%` |
| 已通过题识别准确率 | 同步结果与 LeetCode 页面抽样核对一致的题目数 / 抽样题目数 | `>= 99%` |
| 去重正确率 | 重复同步后未产生重复题目的测试次数 / 总重复同步测试次数 | `100%` |
| 数据损坏事件 | 同步或排期造成题库、笔记或历史不可恢复丢失 | `0` |
| 计划容量正确率 | 今日任务不超过用户题数上限的正常场景 / 被测正常场景 | `100%` |
| 计划生成性能 | 本地存在 3000 道题时生成今日计划的耗时 | `<= 2 秒` |

### 9.2 用户价值指标

在不少于 20 名目标用户、持续 4 周的受控试用中评估：

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 激活率 | 安装后 10 分钟内完成同步、设置容量并生成计划的用户比例 | `>= 80%` |
| 首次复习率 | 激活后 24 小时内至少完成 1 道复习的用户比例 | `>= 60%` |
| 周计划完成率 | 每名活跃用户已完成任务数 / 当周计划任务数的中位数 | `>= 60%` |
| 七日留存率 | 激活后第 7 天仍完成至少 1 道复习的用户比例 | `>= 30%` |
| 自定义控制成功率 | 加入、移出、暂停和恢复后计划结果正确的验收比例 | `100%` |

首版默认不上传行为统计。开发测试通过本地测试报告记录；受控试用如需收集匿名指标，必须先说明数据范围并取得用户明确同意。

## 10. T-008：首版范围冻结

### 10.1 首版 P0 纳入范围

- Chrome 与 Edge 桌面扩展；
- `leetcode.cn` 单账号登录状态识别；
- 用户主动触发的已通过题目同步；
- 题目去重、增量更新和同步结果提示；
- 个人题库搜索、筛选、排序和批量管理；
- 用户决定加入、移出、暂停、恢复、毕业或忽略题目；
- 按每日题数上限生成复习计划；
- 四档掌握反馈和重新排期；
- 今日复习、复习历史和个人笔记；
- 基础日历、完成率、掌握状态和未来任务量；
- 数据导出、账号解绑、账号数据删除和清除全部数据；
- 会话失效、网络错误、字段缺失和接口变化的保护性处理。

### 10.2 首版 P1 或后续范围

- 自动定时同步；
- 按预计时间而非题数控制每日容量；
- 面试冲刺、日常巩固等复习目标；
- 系统通知和每日提醒；
- 多设备冲突处理；
- 难度与标签掌握分布等增强统计。

### 10.3 明确排除范围

- `leetcode.com` 全球站和其他刷题平台；
- 移动端、Firefox 和 Safari；
- 完整历史首次通过时间回填；
- 失败提交同步和代码质量分析；
- 在线代码编辑器、代码执行和判题；
- 自动生成完整题解或答案；
- 社区、动态、排行榜和用户间比较；
- 云端账号、云备份和跨设备同步；
- 团队、班级或培训机构管理；
- 商业化和未经许可的公开商店分发。

任何范围变更必须记录变更原因、对隐私和数据源的影响、优先级及对应验收项，不能直接加入开发。

## 11. 风险登记

| 风险 | 等级 | 当前控制措施 | 放行条件 |
| --- | --- | --- | --- |
| 未获得 LeetCode 第三方插件授权 | 严重 | 仅做个人本地原型，不公开分发 | 获得书面许可或切换到明确允许的数据源 |
| 内部 GraphQL 字段或端点变化 | 高 | 数据适配层、结构校验、失败不覆盖、手动重试 | 登录测试账号验证通过，并建立接口契约测试 |
| 完整历史通过时间不可用 | 中 | 标记时间来源，旧题使用同步基准但不冒充完成时间 | 页面正确解释并通过验收 |
| 登录态读取涉及敏感凭据 | 高 | 不读取和保存密码、Cookie、Token；使用最小权限 | 安全评审和权限清单通过 |
| 频繁请求触发限流或影响平台 | 高 | 主动同步、分页低频读取、退避、禁止无限重试 | 限流测试通过，且符合平台许可 |
| 本地数据随卸载丢失 | 中 | 常驻导出入口、删除影响提示 | 导出和恢复流程通过验收 |
| 多账号误关联 | 中 | 首版只允许单账号，账号变化时停止并提示 | 账号切换测试通过 |

## 12. 后续阶段强制约束

1. 复习算法不得依赖完整历史通过时间一定存在。
2. 所有来源数据写入前必须校验，空响应不得触发全量删除。
3. 用户手动设置的复习状态优先于平台同步状态，不能被重复同步覆盖。
4. 插件不得收集或保存 LeetCode 登录凭据和用户提交代码。
5. 首版同步必须由用户主动触发，自动同步保持为 `P1`。
